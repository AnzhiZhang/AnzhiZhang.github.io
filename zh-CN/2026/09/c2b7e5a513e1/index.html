Hermes Agent 部署与实践

Hermes 是一个 AI Agent。本文简单记录部署过程与个人的实践方式和感悟。

Hermes Agent 部署

安装非常简单，使用提供的脚本一键安装。

安装好后即可使用。我自己接入了第三方模型，并且接入了飞书。

如果需要的话，可以配置下 Firecrawl，支持官方或自建，毕竟浏览网页还是很重要的，官方注册后提供 API 账号就行了。

群聊实践

个人觉得目前最佳的使用实践就是一个项目或事情建一个群，就像工作哪怕是差不多的同事，也一个项目建一个群，一事一议。群里给 bot 发消息需要 @，可以配置下让 Hermes 回复每一条消息。

新的个人助理

Agent 的正确使用方式，其实是一个年薪 6 万（认真估了价的）的个人助理。

有一种说法叫 dirty work，指的是那种琐碎、麻烦、低收获感的工作，也就是实习生常做的工作，我聊的几个人今年都因为 AI 开掉了手底下的实习生，这就是实实在在提高了工作效率的应用。

使用个人 Agent 同理，把它当个人助理，当实习生来用，它也有一个完整的电脑，像 WorkBuddy、Grok Bot、Muse 一样，让它来解决实际的问题，把我们的层级放高，让它自己搞定或教它去做，而且只需要教一次。

服务器运维

传统运维需要敲大量命令，编辑配置文件，检查运行状态，各种重启服务，还有因为对配置不熟悉的反复测试，甚至很多时候是因为强迫症。现在用 AI 完成这部分工作，只需要对着聊天喊一嗓子，就可以完成敲命令好几步的工作。虽然有 omz，但是来回切换目录，查看配置，修改保存的时间和精力，还是没有喊一句话来得方便和舒服。说什么命令行是最优雅的界面，实际上真有几个喜欢的？

而且 AI 最强大的能力，其实是命令的拼接。我们经常能看到它组合各种命令来完成需求，加上配置文件的编写能力，比人类强大太多了。高级的运维工程师指挥 AI 来完成工作，比初级的运维熬通宵干得又快又好。

我还可以直接用 Agent 来检查各项服务的状态和运行情况，比自己查询 docker 日志，然后查看应用日志，工作效率提升了，理解难度也降低了。

个人日程管理

正常助理可以做日程管理，Agent 当然也可以，把需要提醒的事情告诉他，它也可以结合日历和邮件管理日程，这是各家大厂成熟产品一直在吹的功能，不多赘述。

实际上我真用到的功能，是搞了个看网络小说整理人名和人物关系的功能。

办公需求脚本开发与使用

如果用邮件比较多，很多人可能会有一个痛点，附件太大的邮件会占用空间，但是可能因为正文有用，又不适合直接删除。我以前的解决方案是 Foxmail 可以直接删除邮件的附件，其实就是删掉旧的，重新上传一个不带附件的版本，Thunderbird 也是可以实现的，但是使用邮箱网页版或 Mail 的话，就没有办法解决了。

现有的解决方案有人会开发在线的网页，但是安全性无法保证，自己当然可以搓个脚本实现，那需要大量的调试时间。我用 Hermes + Claude Code 直接实现了这个功能，制作一个脚本加沉淀的 skill，需要的时候喊一声清理，还可以随时定制更新使用方式。

网页信息检索与归集

最近在审一个 PR，最后合并的要求是下掉某个版本之前的 release 附件，因为那些有安全漏洞。其实我根本没有看过这个项目有多少 release，也不想去看，因为大概率有很多，一个个检查太慢了，做了简单的判断之后。

杂谈与感悟

这篇文章读者可能觉得很敷衍，一点没有那种正统技术文章一步步手把手教学的风格。翻一翻我以前的文章，确实不是这样的，在没有 Chatbot 的时代，我们看的博客文章也是手把手教学的那种。但今天，真的不再需要了，我们完全可以向 AI 要一个完全适合自己环境编写的手把手教程，来完成任何的这类软件部署工作，甚至让 Agent 来直接完成工作。最近几个月在各种讨论、沙龙、活动经常听到一句话，问 AI 能得到的答案，就不要再问我了。是啊，问 AI 能得到的答案，就没必要再写那么细了。

Hermes 我用了几天，现在电脑上也部署了一个。借助 Agent 强大的白领工作能力，把以前有一些积累的杂活干完了，开发和运维确实方便，完全不需要盯着 codebase，让 Agent 去鞭策 Claude Code，还可以随时检查部署的服务状态。现在还在开发各种应用场景，目前比较爽的一点是因为接入了飞书，有比较好的话题隔离和通知，但我是坚决不会空闲下来或出去玩也要用手机部署任务的，那样没有意义也不应该，人需要放空思考的时间。

其实今年 AI 模型的迭代真的很快，去年我主要工作还在 Chatbot 上面，复制粘贴来回搬运命令和代码，加上自己的思考和 AI 讨论问题解决方案和思路。今年年初的时候，用 Coding Agent 开发项目，还经常出现那种难以解决的问题。到了今年下半年，我已经丝毫不怀疑 AI 在搬运信息上会出错，而且它在项目开发工作中也能很简单高效的解决问题，开发出来的方案经常比我自己设计的还要好。

Databricks CEO 有一个段子，大家不会觉得我们已经实现了 AGI，但是我们会觉得 AI 比身边的大部分人聪明。这种 AGI 似乎已经来了的时代，要思考的问题，就是如何发挥 AI 的能力。今年有一个趋势，垂直领域 Agent 在快速增长，商业叙事从软件市场转向劳动力市场，真正开始发挥商业价值。WorkBuddy、Grok Bot、Muse，当 AI 落地传统行业，降低人力成本，提升业务效率的时候，它的价值被传统的定价方式重新定义了。

一开始听了用例后，我想的是把 Agent 当秘书用，用了一段时间过后，发现应该当私人助理用。其实应该把 AI 当许愿池用，它自己会找到合适的工具去解决问题。我在飞书里已经建了一些群，链接服务器和电脑上的两个 Hermes，一事一议，真真切切在解决各种实际问题和工作需求。其实我们很多人的工作已经从基础的琐碎和重复工作，变成了把控方向和边界的领导角色，定好任务目标和边界，能够检查交付结果，而且在下属实现不了的时候指出正确的调整方向。

有几点小细节的改变我认为值得提一下，第一，是以前很多讲座和分享需要权衡是否参加，现在我可以无脑报名，有意思就仔细听一听，录制下来或者拿到转录，加上幻灯片丢给 AI 总结，出来一篇文字版的文章，实际上的信息获取成本只有 5 分钟，反而回归了 10 年前那种公众号文章分享的模式。我记得马督工讲过，自己虽然做视频，但是从来不看视频，因为文字获取信息的速度是最快的。第二，是写邮件的时候，以前需要字斟句酌，现在可以一股脑往上糊，词句结合写完之后，交给 AI 整理和润色。这几点是实实在在提高了工作效率的应用场景。

其实 AI 叙事的转变，对个人而言真正产生了什么价值还不好说，我感受到用上之后自己产生了很多新的需求，或者是那种以前随意做的事情现在做得更精进了，真正的生产力或个人成长的帮助，还需要更长期的实践。

有一件很好玩的事情，本文成文后，英文的混排整理，是用 AI 完成的。
